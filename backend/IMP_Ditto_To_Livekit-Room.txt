# 1. What LiveKit actually does with avatars

I checked the current LiveKit avatar documentation.

LiveKit's intended architecture is:

```text
                    AgentSession
                         │
                         │ agent audio
                         ▼
                 Avatar Worker
                         │
              ┌──────────┴──────────┐
              │                     │
              ▼                     ▼
        Audio Track            Video Track
              │                     │
              └──────────┬──────────┘
                         ▼
                    LiveKit Room
                         │
                         ▼
                     Frontend
```

The avatar is **not simply a video file/stream attached to the frontend**.

LiveKit says that the avatar plugin creates a **separate participant** in the room, and that participant publishes synchronized audio + video tracks. ([LiveKit Docs][1])

This is exactly why you previously saw:

```text
anam-avatar-agent
```

as a participant.

That behavior was correct.

LiveKit explicitly describes the avatar as a **secondary participant / avatar worker**. ([LiveKit Docs][1])

A custom avatar worker can tell the agent session when audio playback has **actually started** on the worker.

This will be very useful once we implement the real Ditto worker.
